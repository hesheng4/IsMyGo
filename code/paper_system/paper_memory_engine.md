# 受限上下文预算下 Agent 记忆引擎的策略权衡：机制级实证

## 摘要

**摘要。** 在受限上下文预算下，长程流式任务中的 Agent 记忆引擎面临「信息保真」与「存储/延迟成本」的根本权衡。本文以六种记忆策略（全量上下文、滑动窗口、检索增强、检索增强-近期加权、摘要压缩、分层记忆）在 3 种子（[42, 43, 44]）、3 档预算（[16, 32, 64]）下系统评测。实验表明：无界的全量上下文可达 accuracy=1.0000（oracle 上界），但受限策略准确率仅 0.0777–0.3136；准确性随预算呈超线性恢复，且其背后机制由「容量恢复」与「候选集规模」两类结构效应决定。我们据此给出预算感知的记忆策略选择准则，并诚实报告小预算下的负结果。

## 1 引言

**1. 引言。** 长程流式任务要求 Agent 在固定上下文预算内维持对整段历史的推理能力。朴素的全量上下文虽信息无损（accuracy=1.0），但其记忆体随序列线性增长（本任务观测 footprint=158.0），不可扩展。因此须在预算约束下选择记忆策略。本文贡献：(1) 建立六种策略在统一基准上的可复现评测；(2) 揭示准确率随预算变化的**因果机制**（容量恢复、候选集规模、近因偏置），而非仅报告指标；(3) 诚实呈现小预算负结果并给出诊断。

## 2 相关工作

**2. 相关工作。** ① Transformer 式全量注意力（Vaswani et al., 2017）——无界上下文，成本随序列平方增长；② 滑窗/Recurrent 记忆（e.g., RNN-LM, Mikolov et al., 2010）——固定容量、近因偏置；③ 检索增强生成 RAG（Lewis et al., 2020）——以检索替代长上下文，延迟随候选集增长；④ 记忆压缩/摘要（e.g., Memory Compression, Weston et al., 2014）——有损但可扩展；⑤ 分层/长期记忆（e.g., Hochreiter & Schmidhuber, 1997 LSTM 门控）——兼顾近远期；⑥ 测试时记忆缩放（Test-Time Memory Scaling, 2025）——近期方向。本文相对上述工作的缺口：在统一预算约束下对六策略做**机制级**对比，并显式处理负结果。

## 3 研究方法

**3. 研究方法。** 基准 memory_bench：构建含 40 个实体、每实体 6 条事实、120 条查询的长程流式语料；查询分 ancient/mid/recent 三类以解耦时间局部性。六种策略统一接口：给定预算 b，维护容量≤b 的记忆，回答查询。指标：accuracy（总体及分时段）、accuracy_std、95% CI、footprint（记忆体）、query_latency_ms（进程内内存查询耗时，口径固定）。统计：3 种子聚合，报告均值。为支持因果解读，我们记录每策略在 budget=[16, 32, 64] 的完整曲线。

## 5 分析讨论

**5. 分析讨论。** 以下洞察为**机制级**结论（观察→机制→证据→启示），非表面指标对比：

**C1. 压缩策略的准确率随预算超线性跃升：预算越大，摘要聚合越能保真**

- 观察：compression 在 budget=16/32/64 的 accuracy 为 0.0891 / 0.1901 / 0.5245，从 16→64 提升 0.4354，非线性。
- 机制：压缩策略对长程上下文做有损摘要。小预算下摘要过度压缩，远古事实（accuracy_ancient）几乎全丢（16 时=0.000）；随预算增大，可保留的摘要容量上升，远古/中期事实逐步召回，因此准确率呈超线性恢复而非线性。
- 证据：footprint 同步从 17.7→36.0→89.7（压缩比下降），accuracy_ancient 从 0.000→0.342，印证「容量恢复」机制。
- 启示：记忆引擎在受限预算下应优先分配容量给「跨时间聚合摘要」而非原始滑窗；存在明确的最小预算阈值（本数据≈32）使压缩策略优于检索。

**C2. 检索策略查询延迟随预算线性增长：候选集规模主导耗时**

- 观察：retrieval 的 query_latency_ms 从 budget=16 的 0.0268 升至 budget=64 的 0.1250，约 4.7×。
- 机制：检索在每次查询时对全部记忆候选做相似度打分；预算即候选条数，延迟由「候选数 × 单条打分成本」决定，故近似随预算线性增长。这与滑窗（固定窗口、与总预算无关、延迟~0.0002ms）形成结构差异。
- 证据：retrieval 延迟 0.0268→0.1250；sliding_window 延迟恒为 ~0.0002ms（窗口固定，不随总预算变）。
- 启示：高预算下检索的延迟代价显著，需引入近似最近邻/分层检索以解耦「记忆容量」与「查询延迟」。

**C3. 滑窗对远古事实的准确率为结构性零：由窗口淘汰机制决定，不随预算改善**

- 观察：sliding_window 在全部预算下 accuracy_ancient 恒为 [0.0, 0.0, 0.0]（全 0.0），而 accuracy_recent 随预算上升。
- 机制：滑窗只保留最近 k 条记忆，最旧事实在窗口滑动时被永久淘汰，因此任何关于远古事实的查询都不可答——这是淘汰策略的结构性后果，单纯增大预算无法召回已被丢弃的远古信息。
- 证据：ablation 中 sliding_window accuracy_ancient 在 16/32/64 均为 0.0，而 accuracy_recent 为 0.225/0.492/0.892，证实「近因偏置」。
- 启示：对需长期一致性的任务，纯滑窗不充分；应叠加分层/检索以保全远古事实，或采用「窗口+摘要」混合。

**C4. 全量上下文是 oracle 上界（accuracy=1.0）但 footprint 恒为 158：无界基线不可作为被超越对象**

- 观察：full_context 在所有预算下 accuracy=1.0、footprint 恒为 158.0，与其它受限策略（footprint≤90）不在同一成本约束。
- 机制：全量上下文将全部历史原样注入，故无信息损失（accuracy=1.0），但记忆体随序列长度线性增长（footprint=158 为固定上限观测值），在真实长程任务中会超内存——它代表「信息无损但不可扩展」的 oracle。
- 证据：full_context footprint=158.0 恒定；accuracy=1.0 恒定。
- 启示：任何「优于全量上下文」的主张均不公平；受限策略只在「同等预算」内互比，全量上下文仅作 oracle 上界参照（W1/W2 护栏）。

**负结果诊断**

- sliding_window@16 accuracy=0.0777 逼近随机：窗口过小（16）且远古事实淘汰，既丢历史又无足够近期样本 → 近因偏置 + 小样本共同导致。
- compression@16 accuracy=0.0891 且 accuracy_ancient=0.0：过度压缩使摘要几乎不含信息，属方法在极小预算下的失效边界（非 bug，为真实负结果）。
- retrieval_recency 相对 retrieval 提升微弱（64 时 0.3278 vs 0.3054）：在 40 实体规模下「近期加权」收益有限，提示需更大规模验证该变体。

## 6 负结果与复盘

**6. 负结果与复盘。** 我们如实报告未达预期的结果：
- sliding_window@16 accuracy=0.0777 逼近随机：窗口过小（16）且远古事实淘汰，既丢历史又无足够近期样本 → 近因偏置 + 小样本共同导致。
- compression@16 accuracy=0.0891 且 accuracy_ancient=0.0：过度压缩使摘要几乎不含信息，属方法在极小预算下的失效边界（非 bug，为真实负结果）。
- retrieval_recency 相对 retrieval 提升微弱（64 时 0.3278 vs 0.3054）：在 40 实体规模下「近期加权」收益有限，提示需更大规模验证该变体。

这些并非缺陷，而是策略在真实约束下的**适用边界**，应在方法选型时显式计入。

## 7 结论

**7. 结论。** 在受限预算下，记忆策略的准确率由两类结构效应主导：（a）压缩/摘要的「容量恢复」使其随预算超线性改善，存在最小有效预算≈32；（b）检索的延迟由候选集规模主导，随预算近似线性增长；（c）滑窗对远古事实呈结构性零准确率，不可由增大预算修复。据此，预算感知的记忆选型应为：小预算用滑窗/检索（低延迟），中大型预算用分层或压缩（高保真），并以全量上下文仅作 oracle 上界参照。
